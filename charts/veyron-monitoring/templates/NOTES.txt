VMRogue monitoring stack (Prometheus Operator + Prometheus + Grafana + Alertmanager).

1) Grafana (default admin user: admin)

   Password from chart value kps.grafana.adminPassword (override for production).

     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-grafana 3000:3000

2) Prometheus UI

     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-kps-prometheus 9090:9090

2b) Alertmanager

     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-kps-alertmanager 9093:9093

3) VMRogue UI

   With the API in namespace "{{ .Values.vmrogue.namespace }}", the Monitoring page should show
   Prometheus / Grafana as "In cluster" when this release lives in a scanned namespace
   (e.g. monitoring, prometheus, observability) or matches your API default namespace.

4) KubeVirt metrics

   Dashboard panels and VM alerts expect kubevirt_* series. Ensure KubeVirt exposes metrics
   to Prometheus (KubeVirt ServiceMonitor / recommended monitoring docs) so queries are non-empty.

5) Disable the bundle

   helm upgrade {{ .Release.Name }} ./charts/vmrogue-monitoring -n {{ .Release.Namespace }} --set kps.enabled=false
